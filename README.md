# 苏丹的游戏 MCP

这是给《苏丹的游戏》玩家用的 AI 陪玩工具。接入后，你可以在聊天里问「今天哪张苏丹卡快到期了？」「这个仪式能派谁去？」AI 可以读取你最近保存的回合，查看手里的牌、人物去向和本机生效的游戏规则，再给你建议。怎么出牌、选哪条剧情，仍由你在游戏里决定。

## 它解决什么问题

攻略能告诉你一个仪式需要什么牌。到了自己这局，还得查那张牌在不在手里、合适的人是不是已经派出去了、装的模组有没有改条件。直接问 AI，往往还要先截图或把局面复述一遍。这个 MCP 把存档和游戏配置接到聊天客户端，让 AI 可以自己查这些事实。

比如，你遇到「赤字滔天」，想知道**能不能只交钱，把擅长交涉的人留给另一个仪式**。客户端可以先查该仪式的缴款和交涉分支，再对照你这局的金币、候选人和他们正在做的事。你还可以追问「这个判断依据哪条规则？」，让它给出仪式配置 ID `5006585` 和对应格子的条件。

## 谁适合用

| 如果你正在…… | 可以这样问 |
| --- | --- |
| 第一次玩，经常过了回合才发现漏处理了一张牌 | 「只说今天，再等一天会错过什么？先别剧透后面的剧情。」 |
| 同时推进几条剧情，或隔了几天才回来接着玩 | 「上回合我把谁派出去了？哪些是已经做的决定，哪些只是记下的计划？」 |
| 装了创意工坊模组，发现手里的牌放不进攻略说的格子 | 「按我装的版本，这个格子要求什么？哪些人物空闲，哪些还在别的仪式里？」 |

面向使用 Windows 版游戏、愿意在聊天客户端里接入本地工具的玩家。连接后用中文提问即可。想约定剧透范围或让 AI 记住本局目标，可以从这份提示词开始。[军师提示词](军师提示词.md)

## 本地运行

准备 64 位 Python 3.11、Windows 版《苏丹的游戏》和一个支持 MCP 标准输入输出（stdio）的客户端。服务使用 Python 标准库，在 CPU 上建立和检索索引。

**1. 下载项目，确认能读到存档。** 在 PowerShell 中运行以下命令，把游戏目录改成你的安装位置。运行 `saves` 后应能看到当前回合和存档文件列表。

```powershell
git clone https://github.com/clud32/sultan-mcp.git
cd sultan-mcp
$env:SULTAN_GAME_DIR = "D:/SteamLibrary/steamapps/common/Sultan's Game"
python -X utf8 server.py saves
```

**2. 把服务加到客户端。** 以下是使用 `mcpServers` 配置格式的示例。把 `args` 中的脚本路径换成 `(Resolve-Path ./server.py).Path` 显示的绝对路径，游戏路径与上一步保持一致。如果客户端找不到 Python，把 `command` 换成 `(Get-Command python).Source` 显示的路径。JSON 路径可以使用正斜杠。

```json
{
  "mcpServers": {
    "sultan": {
      "command": "python",
      "args": ["-X", "utf8", "D:/repos/sultan-mcp/server.py"],
      "env": {
        "SULTAN_GAME_DIR": "D:/SteamLibrary/steamapps/common/Sultan's Game"
      }
    }
  }
}
```

**3. 重新加载服务，问第一句话。** 试试「用苏丹工具看一下，我现在是第几天，读的是哪个存档？」把回答中的回合和文件名与游戏对上，再问当天的局面。工具能看到的是游戏最近一次保存的状态。

<details>
<summary>存档、模组和个人笔记的位置</summary>

| 内容 | 默认位置与读取方式 |
| --- | --- |
| 存档 | 从 Windows 用户目录下的 `AppData/LocalLow/DoubleCross/SultansGame/SAVEDATA` 查找。优先读 `auto_save.json`，缺少自动存档时读最近修改的回合快照。可用 `SULTAN_SAVE_DIR` 指定存档目录。 |
| 模组 | 按加载顺序读取已启用模组的配置。默认使用同一 Steam 库的 `steamapps/workshop/content/3117820`，跨库安装时可设置 `SULTAN_WORKSHOP_DIR`。 |
| 工具生成的文件 | 日报、目标、个人笔记和索引缓存写入仓库根目录下的 `.local/`，可用 `SULTAN_STATE_DIR` 改位置。读取局面时可能自动生成当日日报。随项目提供的攻略笔记在 `kb_seeds/`，个人新增笔记写入状态目录的 `kb_seeds/`。 |

服务只读游戏安装目录和存档，并把查询结果返回给发起调用的客户端。

## 工具与判断依据

| 想查的事 | 可用工具 |
| --- | --- |
| 当前局面、人物、倒计时，以及两个回合之间发生了什么 | `overview`、`cards`、`rites`、`counters`、`saves`、`diff`、`log`、`upcoming` |
| 仪式格子、剧情条件、路线进度和配置来源 | `slots`、`cross_check`、`config`、`search`、`long_term`、`line_status` |
| 当日日报、建议、已做的决定和本局目标 | `daily_report`、`save_advice`、`journal`、`goals` |
| 查攻略、读整条规则、记新经验和重建索引 | `kb_search`、`kb_get`、`kb_add_seed`、`kb_rebuild` |

问「谁能放进这个格子」时，`cross_check` 可以指出候选人现在在哪，`slots` 会把单张卡就能判定的候选与还要看其他格子或计数器的候选分开。碰到关键剧情选择，可以用 `config` 查看生效配置及其来源。解析器保留配置中重复出现的同名条件，方便核对各个分支。

问规则或攻略时，`kb_search` 用 BM25 检索仪式、事件、卡牌、结局和攻略笔记。中文按单字及相邻双字切分，对名称和攻略笔记加权。每条结果带有文档 ID，可用 `kb_get` 读全文。游戏或模组更新后可用 `kb_rebuild` 重新索引。

## 测试环境声明

2026-11-24 在 Windows 11 家庭中文版（10.0.26200，AMD64）、CPython 3.11.9 64 位、Steam 游戏 Build ID `25901963` 上测试。真实安装启用了 3 个含配置的创意工坊模组，使用结局后保留的回合快照。集成测试从空缓存和临时状态目录启动服务，通过 stdio 使用 MCP 协议 `2025-06-18`。[完整测试记录](tests/results.json)

## 测试结论

| 检查项目 | 结果 |
| --- | --- |
| 合成存档回归 | 6/6 通过。覆盖协议握手、工具发现、读档、未知工具、笔记写入范围，以及缺少自动存档时回退到回合快照。 |
| 真实存档集成 | 发现 22 个工具，实际调用 7 个。完成读档、查卡、核对配置、检索和生成日报。读取的回合存档在测试前后 SHA-256 一致。 |
| 攻略检索 | 从本机游戏和 32 条随附笔记构建 4,850 篇文档。170 个问题中，106 个首条命中（62.4%），136 个前三条命中（80.0%）。 |

命中指检索结果包含题目标注的任一参考文档。剩余 34 题在前三条中未找到参考资料，涉及别称、跨路线描述等问法。本轮评测覆盖资料检索，最终回答质量、通关效果、其他系统和桌面客户端界面均未评测。[评测题集](tests/queries.tsv)

在仓库根目录依次运行以下命令。第一项使用合成存档，第二项读取本机游戏和存档，第三项按当前安装重建索引并输出命中统计。

